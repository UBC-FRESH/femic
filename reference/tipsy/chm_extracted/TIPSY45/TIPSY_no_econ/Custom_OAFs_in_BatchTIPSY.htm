Custom OAF File

Custom OAFs

File Format Specifications

When the application of Custom OAFs is activated via a checkbox in the Input Variables dialog box, the following two dialog boxes appear during the dialog wizard process.

Custom OAF File

The Custom OAF File dialog box prompts the user for the name of the Custom OAFs file.   The file format specifications are given below.

Custom OAFs

The Custom OAFs dialog box allows the user to specify up to 5 custom OAFs for each run.  These can be a combination of stand and species specific OAFs, with 3-letter codes corresponding to those defined in the Custom OAF definition file.  The intensity can be one of four single-character codes: blank (no OAF applied), L (low intensity), M (medium intensity) or H (high intensity).  Anything else would generate an error message.

If the user specifies a 3-letter custom OAF identifier that does not appear in the definition file, an error message will be presented to the user and the run will not be completed.  If, however, the user specifies an OAF that does not apply to any of the species in the stand for that particular run, a warning message will be generated to that effect (the run proceeding as normal).

The identifier can also be left blank, indicating that there is no custom OAF (in that position) for this run.

For example:

... OA1 L   OA2 M   OA3 H ...

... OA4 H                 ...

... OA1 L   OA2 L         ...

In the above example, the first run applies the OAFs OA1 (low level), OA2 (medium level) and OA3 (high level).  OA1 and OA2 may apply to specific species, where OA3 is a stand-level OAF (applied to the stand as a whole).  The second run only applies the OAF OA4 (high level), whereas the third run applies OAFs OA1 and OA2, both at the low level.  The user is able to choose from any the OAFs defined within their definition file.

It's important to note that application of species-specific custom OAFs are specified at the stand level in BatchTIPSY (as opposed to interactive TIPSY, where they are specified at the species level).

Like the custom fertilization response file, the custom OAFs data definition file is not read into the system until the user processes the batch file.  Any format errors in this file will result in an error being written to the error file and the batch file will be processed with no custom OAF information.

File Format Specifications

The custom OAF definitions data file must be a text file, formatted as follows:  One "header" line indicating a unique 3-character text identifier for the OAF (i.e. "ARM"), the name of the species (or STAND if it is a stand-level OAF) to which the OAF will be applied, whether or not responses will be specified by age or height, and whether the OAF moves trees to the mortality table ("mort") or removes them from the stand completely ("remove").  Lastly, an optional "long name" would appear on the line such that it could be used as an identifier for use in the TIPSY application.  These "long names" would have to be unique across a species (one species cannot have two OAFs that share the same long name).  Note that the link from the custom OAF definition to a specific species (or the stand in general) is through the 3-character code.

This OAF "header" will be followed by up to 5 lines of response data.  Each line will have 4 values.  The first value is either the age or height in question (depending upon what is specified in the header for that OAF).  The following 3 values are the low, medium and high intensity OAFs for that age or height.

For example a stand level "oaf 2" type OAF could be specified as follows:

OA2, STAND, age, mort, OAF 2

0.0, 1.0, 1.0, 1.0

100.0, 0.95, 0.85, 0.75

300.0, 0.85, 0.70, 0.55

In order that the program reading the data file can distinguish between OAF definitions (i.e., where the definition of one OAF ends and another begins), there must be some indication of how many lines of response data there are for a given OAF.  This can be done in a couple of ways.  Either by indicating the number of responses on the header line:

OA2, STAND, age, mort, OAF 2, 3

0.0, 1.0, 1.0, 1.0

100.0, 0.95, 0.85, 0.75

300.0, 0.85, 0.70, 0.55

or by delimiting each OAF definition with a "!" character (or some other character)

OA2, STAND, age, mort, OAF 2

0.0, 1.0, 1.0, 1.0

100.0, 0.95, 0.85, 0.75

300.0, 0.85, 0.70, 0.55

      !

As many OAFs as desired can be specified, provided they each have a unique 3-character identifier.
