# Phase 115: Forest carbon domain, CBM packages, and GCBM export

Status: active
Branch: `feature/p115-forest-carbon`
Parent issue: #361
Related: `UBC-FRESH/ws4` Phase 51; `UBC-FRESH/ws3` libcbm reference lane

## 1. Goal

Give FEMIC a reviewed, versioned carbon domain and make it the producer of the static CBM input
packages that WS4 and WS3 consume. Add a GCBM walltowall export bridge so the same inventory can be
run through the spatially explicit CBM runtime when a spatial or peatland question requires it.

## 2. Why FEMIC owns this

FEMIC already knows the inventory, the growth and yield curves, the analysis units, the species
shares, and the provenance of each source. WS4 knows the compiled matrix and the schedule, but it
does not own the science crosswalks that turn a BC inventory into CBM classifiers.

Keeping the static crosswalks and the package contract in FEMIC:

- gives one reviewed place for species, eco-boundary, land-class, and disturbance mappings;
- lets WS4, WS3, and a GCBM project consume the same package;
- keeps the WS4 compiled dataset free of carbon-specific columns;
- makes the carbon provenance auditable at the producer.

## 3. Responsibility boundary

### FEMIC

- Package schema, units, rounding, and manifest.
- BC species to CBM species crosswalk.
- TSA/AU to CBM eco-boundary mapping.
- Land-class defaults and historical/last-pass disturbance defaults.
- Initial inventory and yield tables in SIT-compatible form.
- WS4 treatment label to CBM disturbance-type mapping.
- GCBM walltowall configuration and spatial layers.
- Package validation and fixtures.

### WS4

- Join the package to the compiled dataset by track name.
- Build schedule-dependent SIT events and treatment-dependent transitions.
- Run the engine, write carbon outputs, and expose carbon accounts and targets.
- Verify the final schedule with the exact engine.

### WS3

- Reference implementation and parity oracle.
- Keep `to_cbm_sit()` working against current libcbm.
- Provide a known-good fixture and initial carbon totals.

## 4. Package contract

The package is a directory with a manifest and reviewable CSV tables:

```text
carbon_package/
  manifest.json
  classifiers.csv
  disturbance_types.csv
  age_classes.csv
  inventory.csv
  yield.csv
  track_carbon_map.csv
  curve_carbon_map.csv
  species_map.csv
  disturbance_map.csv
  boundaries.csv
  README.md
```

The exact columns, units, and validation rules are defined in
`docs/reference/contracts/carbon-domain.rst` (P115.1). The key design choices:

- **Track name is the join key.** Dataset-local track ids are not durable.
- **The manifest records provenance.** Source hashes, producer version, `cbm_defaults` version and
  hash, units, boundaries, and the event/transition source.
- **The package is static.** Events and transitions are generated by WS4 from its schedule and
  treatment table; the package does not pretend to know a schedule.
- **Species resolution is explicit.** If only softwood/hardwood shares are available, the package
  declares them as components and records the limitation. A missing share is an error, not a silent
  zero.

## 5. Crosswalks

### Species

The first version needs a documented BC species code to CBM default species mapping, with a
softwood/hardwood fallback. The mapping is versioned and sourced. A coarse fallback is acceptable
only when the package marks it and the consumer reports it.

### Eco boundary

CBM uses an administrative and ecological boundary to select decay and other default parameters.
The first version supports a single boundary per package. A TSA/AU to boundary table is reviewed and
recorded. Multi-boundary packages are a later extension.

### Disturbance

Each WS4 treatment label gets its own SIT user disturbance type, mapped to a CBM default disturbance
type. This keeps transition rules unambiguous even when two treatments map to the same CBM type.
Treatments that do not remove biomass are marked explicitly.

## 6. GCBM export bridge

The bridge emits a GCBM 2.5.1-compatible project:

- walltowall JSON configuration,
- initial age and classifier rasters,
- disturbance layers with year and type metadata,
- mean annual temperature layer where available,
- AIDB reference and provenance,
- an export manifest with layer hashes, resolution, CRS, and NoData.

The bridge does not run FLINT in CI. A smoke run is performed on a host with the GCBM toolchain, and
the external dependencies are documented. CaMP/peatlands are out of scope for the first bridge.

## 7. Validation

- Area conservation between the package inventory and the fragment inventory.
- Every classifier value used by the inventory exists in the classifier table.
- Every treatment label has a disturbance mapping.
- The manifest hashes are stable for the same inputs.
- A TSA24 package validates and a second run is stable.
- The WS3 reference run records initial pools and a no-disturbance trajectory.
- The GCBM export prepares on a supported host.

## 9. Risks and open questions

- The species crosswalk needs CBM/CFS review; the fallback must be visible.
- The eco-boundary table needs a reviewed TSA/AU source.
- The MKRF instance may be annex-backed; fixtures must not depend on unavailable pointers.
- GCBM tooling is Windows/Access oriented; the bridge must state what it can and cannot run in CI.
- CBM4 is not public yet; the package remains the stable contract and the engine stays replaceable.

## 10. CBM4 and platform adapter readiness

The package and SIT tables remain the stable contract. libcbm 2.10.2 is the current
driver, pinned with CBM defaults 1.2.9300.391. CBM4 is treated as unreleased: public CFS
material from May 2026 targets open-source availability in the latter half of 2026, but no
public CBM4 package or input schema is pinned. A future CBM4 adapter must preserve the
package, the exact `track_name` join, the `carbon.*` account names, and the TSA24 parity
tolerance. No unreleased CBM4 code or dependency is added. GCBM remains the external
spatial bridge; `gcbmwalltowall convert` is a watchlist path, not a FEMIC runtime
dependency.
