# P117.1 feasibility close-out: ALS site-index layer

Phase: P117.1 Add an ALS site-index / potential-height layer
Parent issue: #374
Task issue: #375
Branch: `docs/p117.1-site-index-feasibility`
Date: 2026-11-06
Status: closed — data-blocked; application engine retained

## Question

Can P117.1 produce a defensible `si_als` layer from the current FEMIC LiDAR bundle,
using a published or project site-index coefficient set and a P48/P49 backtest?

## What exists

- `femic.efi.model.v1` model-card contract.
- `femic.efi.coefficients.v1` linear application engine.
- Applicability checks and a backtest harness.
- A synthetic pilot card and coefficients in `tests/fixtures/efi/`.
- FEMIC P79 LiDAR products with CHM/canopy metrics.
- Published metadata-only cards:
  - White et al. (2015), CWH Lorey's mean height, Random Forest, no coefficients;
  - Gopalakrishnan et al. (2019), southeastern USA loblolly pine, ALS height +
    Landsat age, non-linear, not BC CWH.

## Blocker 1: no transferable coefficient set

The P117.1 source list names:

- Tompalski et al. (2022), poplar-clone site index from ALS;
- Gavilan-Acuna et al. (2022), radiata-pine potential height.

Neither is a BC CWH mixed-conifer calibration. The checked-in CWH card targets **height**, not
site index, and is a Random Forest model without published coefficients. The site-index card is
for southeastern USA loblolly pine and is not the linear form in
`femic.efi.coefficients.v1`.

The synthetic pilot card is explicitly marked "not a published model". Using it for a real
`si_als` layer would be invented evidence.

## Blocker 2: no plot-level ALS backtest surface

ws4 P48/P49 are volume, DBH, height, and stems validation phases. They do not provide:

- a site-index observation per plot;
- ALS point-cloud or CHM metrics per plot;
- a species/age/region-matched calibration set.

P49 also closed data-limited: zero sites met the pre-registered managed/young sample. The
existing P48/P49 surfaces cannot backtest an ALS site-index model at the fragment level.

## Blocker 3: applicability

Applying a poplar or radiata-pine equation to BC CWH mixed conifer would violate the model
card's applicability domain. The P117 risks already state that site-index equations are
species- and region-specific and that ALS height is not site height. A layer built on that
transfer would be worse than no layer because it would look authoritative while being
out-of-domain.

## Decision

**Close P117.1 as data-blocked.** Do not invent coefficients, transfer an out-of-domain model,
or present the synthetic fixture as a real layer.

Retain the application engine, model-card contract, synthetic fixture, and tests as reusable
infrastructure. They are valid for a future project with a defensible BC coefficient set and
plot-level backtest surface.

## What would unblock it

A future P117.1 can proceed if one of these exists:

- a published BC CWH/TSA ALS site-index model with reusable coefficients and a stated
  applicability domain;
- a project calibration with plot-level site index, species, age, and ALS metrics;
- a formal data-sharing agreement that supplies a plot-level validation surface.

Without one of those, the honest deliverable is the application engine, not a site-index map.

## Consequences

- No `si_als` fragment attribute is added.
- No curve assignment changes.
- P117.2 biomass curves remain a separate decision; they need a published biomass equation and
  carbon conversion, not the SI coefficient set.
- No default product, tag, or release change.
